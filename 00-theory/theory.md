## Урок 1. Базы данных и СУБД

- **База данных** = структурированное хранилище данных.
- **СУБД** = совокупность языковых и программных средств, которая:
  - осуществляет доступ к данным
  - позволяет их создавать, изменять и удалять  
  - обеспечивает безопасность данных

**Простыми словами:** СУБД — это система, позволяющая манипулировать базами данных.

> 💡 **Мой инсайт:**  
> Если **БД** — это библиотека (хранилище книг), то **СУБД** — это профессиональный библиотекарь.

### Мировой рейтинг СУБД (2026)
Согласно данным [DB-Engines](https://db-engines.com/en/ranking):

| Место | СУБД          | Тип          |
|-------|---------------|--------------|
| 1     | Oracle        | Реляционная  |
| **2** | **MySQL**     | **Реляционная** |
| 3     | SQL Server    | Реляционная  |
| 4     | PostgreSQL    | Реляционная  |
| 5     | MongoDB       | NoSQL        |

### ✅ Проверка знаний
**Правильно:** СУБД управляет данными, хранящимися в БД.

## Урок 3. Реляционные базы данных
**Как устроены:**
- 📋 **Таблицы (отношения)** — двумерные структуры.
- 📋 **Столбцы (поля)** — фиксированный тип данных.
- 📋 **Строки (записи)** — данные об одном объекте.
- 🔑 **Первичный ключ** — уникальный ID записи.
- 🔗 **Внешний ключ** — связь между таблицами.

**Особенности:**
- ✅ Строгая типизация колонок (число, текст, дата)
- ✅ Результат любого запроса = таблица
- ✅ Каждая ячейка = одно значение

### Золотой стандарт ACID
1. **Atomicity (Атомарность):** Транзакция выполняется полностью или никак.
2. **Consistency (Согласованность):** Данные всегда соответствуют правилам базы.
3. **Isolation (Изолированность):** Параллельные транзакции не мешают друг другу.
4. **Durability (Надежность):** Если данные сохранены, они не исчезнут при сбое.

## Урок 4. Key-value базы данных (Ключ-Значение)

- **Ключ (Key):** Уникальный идентификатор (как номер ячейки).
- **Значение (Value):** Данные, привязанные к ключу (любой формат).

**Примеры:** Redis, Memcached

**✅ Плюсы:** Максимальная скорость, простота, гибкость.
**❌ Минусы:** Нет SQL, нельзя искать по содержимому (только по ключу).

> 💡 **Когда использовать:**  
> Кэш, сессии, счетчики. **НЕ** для сложной аналитики.

## Урок 5. Документоориентированные БД

**Как устроены:**

Вместо таблиц - **Коллекции**, а вместо строк — **Документы**.

**Примеры:** MongoDB, Amazon DocumentDB, Couchbase

**✅ Плюсы:** Нет строгой схемы (гибкость), нативный JSON.
**❌ Минусы:** Дублирование данных, большой объем памяти, слабая согласованность.

> 💡 **Когда использовать:**  
> API, микросервисы, прототипы.

## Урок 6. Структура реляционных таблиц

### Таблица

* **Поля (Attributes / Columns):** Столбцы, у каждого из которых есть свое имя и **строгий тип данных**.
* **Записи (Rows / Tuples):** Строки с конкретными данными.

### Основные типы данных:
* `INT` (или `INTEGER`) — целые числа (например, ID или возраст).
* `VARCHAR(N)` — строки текста длиной до N символов (например, имя).
* `DATETIME` — дата и время (например, дата рождения).

> **Команда для проверки структуры:** > `DESCRIBE название_таблицы;`

**✅ Проверка знаний:** Первичный ключ обеспечивает **уникальность**, а Внешний ключ — **связь таблиц**. У них разные цели!
**❌ НЕВЕРНО:** Правила первичного и внешнего ключа служат для одной цели

## Урок 7. Что такое SQL?

**SQL = Structured Query Language** (язык структурированных запросов)

**Основные команды (CRUD):**

- ➕ C — CREATE (создать/INSERT)
- 📥 R — READ (читать/SELECT)  
- ✏️ U — UPDATE (обновить)
- 🗑️ D — DELETE (удалить)

### Диалекты SQL

| Диалект | СУБД | Особенности |
| :--- | :--- | :--- |
| **MySQL SQL** | **MySQL** | Самый популярный в веб-разработке (используем в этом курсе). |
| PL/pgSQL | PostgreSQL | Мощный, поддерживает сложные вычисления. |
| T-SQL | MS SQL Server | Диалект от Microsoft. |
| PL/SQL| Oracle | Промышленный гигант. |
