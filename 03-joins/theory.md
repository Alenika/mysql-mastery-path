## Урок 1. Многотабличные запросы, JOIN

### 💡 Ключевые моменты

- `JOIN` объединяет таблицы по связующим полям.  
- `ON` задаёт условие соединения (например, `payments.member_id = family_members.member_id`).  
- Рекомендуется использовать псевдонимы (`AS`) для читаемости запросов.  
- Всегда явно указывай таблицу для полей, особенно при соединении (например, `fm.member_name`).

### Общая структура многотабличного запроса

```sql
SELECT поля_таблиц
FROM таблица_1
[INNER | [LEFT | RIGHT | FULL] [OUTER]] JOIN таблица_2
    ON условие_соединения
[[INNER | [LEFT | RIGHT | FULL] [OUTER]] JOIN таблица_n
    ON условие_соединения]
```

### Пример: Payments + FamilyMembers

```sql
-- Без псевдонимов
SELECT
    member_name,
    amount * unit_price AS price
FROM Payments
INNER JOIN FamilyMembers
    ON Payments.family_member = FamilyMembers.member_id;

-- С псевдонимами (рекомендуется)
SELECT
    fm.member_name,
    pay.amount * pay.unit_price AS price
FROM Payments AS pay
INNER JOIN FamilyMembers AS fm
    ON pay.family_member = fm.member_id;
```

## Урок 2. Внутреннее соединение INNER JOIN

### 💡 Что делает INNER JOIN

- Оставляет **только те строки, у которых есть связка в обеих таблицах**.  
- Если записи в одной из таблиц нет, строка не попадает в результат.

### Синтаксис

```sql
SELECT поля_таблиц
FROM таблица_1
INNER JOIN таблица_2
    ON условие_соединения
[[INNER] JOIN таблица_n
    ON условие_соединения]
```

---

## Урок 3. Внешнее соединение OUTER JOIN

### 💡 Ключевые виды

- `LEFT JOIN` — оставляет **все строки из левой таблицы**, при этом подтягивает правую.  
- `RIGHT JOIN` — аналогично, но с правой таблицы.  
- `FULL OUTER JOIN` можно эмулировать через `UNION ALL` (MySQL пока не поддерживает `FULL OUTER` напрямую, поэтому часто используют такой трюк).

### Пример FULL OUTER через LEFT/RIGHT + UNION ALL

```sql
SELECT *
FROM левая_таблица
LEFT JOIN правая_таблица
    ON правая_таблица.ключ = левая_таблица.ключ

UNION ALL

SELECT *
FROM левая_таблица
RIGHT JOIN правая_таблица
    ON правая_таблица.ключ = левая_таблица.ключ
WHERE левая_таблица.ключ IS NULL;
```

## Урок 4. Ограничение выборки, оператор LIMIT

### 💡 Когда использовать

- для постраничной навигации,  
- для выбора первых N записей (топ‑10, топ‑5 и т.п.).

### Синтаксис

```sql
-- Классический вариант
SELECT поля_выборки
FROM список_таблиц
LIMIT [offset,] количество_строк;
```

```sql
-- С ключевым словом OFFSET
SELECT поля_выборки
FROM список_таблиц
LIMIT количество_строк OFFSET количество_пропущенных_записей;
```

## Урок 5. Подзапросы

### 💡 Общее определение

- **Подзапрос** — это вложенный `SELECT`, выполняемый **до** основного запроса.  
- Подзапрос **всегда заключён в круглые скобки**.  
- Его можно использовать в `WHERE`, `FROM`, `HAVING`, `SELECT` и т.д.

### Основной принцип

```sql
SELECT основные_поля
FROM основная_таблица
WHERE поле =
    (SELECT одно_значение FROM другая_таблица);
```

## Урок 6. Скалярный подзапрос (одна строка, один столбец)

### 💡 Что такое скалярный подзапрос

- Подзапрос, который возвращает **ровно одну строку и один столбец**.  
- Его можно использовать с операторами сравнения (`=`, `<>`, `>`, `<`, `>=`, `<=`), а также в `SELECT` как отдельное выражение.

### Пример

```sql
SELECT
    (SELECT name FROM company LIMIT 1) AS company_name;
```

## Урок 7. Подзапросы с несколькими строками и одним столбцом

### 💡 Главное правило

- Если подзапрос возвращает **более одной строки**, его **нельзя** использовать с `=`, `<>` и другими простыми операторами сравнения.  
- Для таких подзапросов используются операторы `ALL`, `ANY`, `IN`.

### Таблица операторов

| Оператор | Возвращает `TRUE`, если... |
|----------|----------------------------|
| `ALL`    | условие верно **для всех** значений из набора |
| `ANY`    | условие верно **хотя бы для одного** значения |
| `IN`     | значение **входит** в набор |

---

### 7.1. Оператор ALL

```sql
-- Проверка: все ли комнаты дешевле 200?
SELECT 200 > ALL(SELECT price FROM Rooms);
```

```sql
-- Найти владельцев жилья, которые НИКОГДА сами не снимали жильё
SELECT DISTINCT name
FROM Users
INNER JOIN Rooms ON Users.id = Rooms.owner_id
WHERE Users.id <> ALL (
    SELECT DISTINCT user_id FROM Reservations
);
```

> 💡 `<> ALL` — это аналог `NOT IN`, но безопаснее при наличии `NULL` в подзапросе.

---

### 7.2. Оператор IN

```sql
-- Найти всех владельцев жилья стоимостью >= 150
SELECT *
FROM Users
WHERE id IN (
    SELECT DISTINCT owner_id FROM Rooms WHERE price >= 150
);
```

---

### 7.3. Оператор ANY

```sql
-- Найти пользователей, у которых есть хотя бы 1 жильё стоимостью > 150
SELECT *
FROM Users
WHERE id = ANY (
    SELECT DISTINCT owner_id FROM Rooms WHERE price >= 150
);
```

---

### 7.4. Эквиваленты

```sql
-- Эти два запроса эквивалентны:
WHERE id IN (SELECT owner_id FROM Rooms WHERE price >= 150)
WHERE id = ANY (SELECT owner_id FROM Rooms WHERE price >= 150)

-- Эти два — тоже эквивалентны:
WHERE id NOT IN (SELECT user_id FROM Reservations)
WHERE id <> ALL (SELECT user_id FROM Reservations)
```

## Урок 8. Подзапросы с несколькими столбцами (многостолбцовые)

### 💡 Идея

- Подзапрос возвращает **несколько столбцов и строк**, то есть “производную таблицу”.  
- В `WHERE` сравниваются **кортежи** (пары/множества значений): `(столбец1, столбец2) IN (SELECT ...)`.

### Синтаксис сравнения по нескольким столбцам

```sql
SELECT ...
FROM таблица
WHERE (столбец1, столбец2) IN (
    SELECT столбецA, столбецB FROM подзапрос
);
```

- Количество столбцов **должно совпадать**.  
- `IN` ищет **точное совпадение кортежей**.

---

### Пример: бронирования с неизменной ценой

```sql
SELECT *
FROM Reservations
WHERE (room_id, price) IN (
    SELECT id, price FROM Rooms
);
```

**Альтернатива через JOIN (часто более читаемо):**

```sql
SELECT Reservations.*
FROM Reservations
INNER JOIN Rooms ON Reservations.room_id = Rooms.id
WHERE Reservations.price = Rooms.price;
```

### Таблица: когда использовать

| Тип подзапроса         | Столбцы | Оператор | Пример                                    | Когда лучше |
|------------------------|---------|----------|-------------------------------------------|-------------|
| Одностолбцовый         | 1       | `IN`, `ANY`, `ALL` | `id IN (SELECT id ...)`            | Фильтрация по ID‑списку |
| Многостолбцовый        | 2+      | `IN` (кортежи)     | `(id, price) IN (SELECT ...)`      | Проверка пар/наборов |

## Урок 9. Коррелированные подзапросы

### 💡 Что такое коррелированный подзапрос

- Подзапрос, **ссылающийся на столбцы внешнего (родительского) запроса**.  
- Такой подзапрос выполняется **для каждой строки** внешнего запроса, а не один раз для всего результата.

### Пример: потратил каждый член семьи

```sql
SELECT
    fm.member_name,
    (
        SELECT SUM(p.amount * p.unit_price)
        FROM Payments AS p
        WHERE p.family_member = fm.member_id   -- ← ссылка на внешний запрос
    ) AS total_spent
FROM FamilyMembers AS fm;
```

## Урок 10. Объединение запросов (UNION)

### 💡 Основная идея

- `UNION` объединяет **результаты нескольких `SELECT` в один общий результат** (по вертикали).  
- `JOIN` объединяет **строки таблиц** по связанному полю (по горизонтали).

### Синтаксис

```sql
SELECT поля FROM таблицы1 WHERE ...
UNION [ALL]
SELECT поля FROM таблицы2 WHERE ...;
```

### UNION vs JOIN

| UNION                     | JOIN                     |
|---------------------------|--------------------------|
| Объединяет **результаты** SELECT | Объединяет **строки** связанных таблиц |
| Независимые SELECT‑запросы | Связанные таблицы        |
| Вертикальное объединение  | Горизонтальное объединение |

### Модификаторы

- `UNION` — объединяет **без дубликатов** (как `UNION DISTINCT`).  
- `UNION ALL` — **сохраняет все строки**, включая повторы (работает быстрее).

## Урок 11. Условная логика, оператор CASE

### 💡 Зачем нужен CASE

- Позволяет делать **условную логику** прямо в SQL: “если… то… иначе…”.  
- Может использоваться в `SELECT`, `WHERE`, `ORDER BY`, `UPDATE` и т.д.

---

### 11.1. Поисковый CASE (WHEN‑форма)

```sql
CASE
    WHEN условие_1 THEN значение_1
    WHEN условие_2 THEN значение_2
    ...
    [ELSE значение_по_умолчанию]
END
```

- Проверки идут сверху вниз, возвращается первое совпадение.  
- Если ни одно условие не подошло и нет `ELSE` → `NULL`.

Пример:

```sql
SELECT
    first_name,
    last_name,
    CASE
        WHEN TIMESTAMPDIFF(YEAR, birthday, NOW()) >= 18 THEN 'Совершеннолетний'
        ELSE 'Несовершеннолетний'
    END AS status
FROM Student;
```

---

### 11.2. Простой CASE (по значению)

```sql
CASE значение
    WHEN значение_1 THEN результат_1
    WHEN значение_2 THEN результат_2
    ...
    [ELSE результат_по_умолчанию]
END
```

- Сравнивает `значение` с каждым `WHEN` через `=`.  
- При первом совпадении возвращает соответствующий `THEN`.

Пример:

```sql
SELECT
    name,
    CASE
        WHEN age >= 18 THEN 'Взрослый'
        WHEN age >= 7  THEN 'Дети'
        ELSE 'Малыш'
    END AS age_group
FROM users;
```

### Таблица различий CASE

| Форма `CASE`               | Когда использовать |
|----------------------------|--------------------|
| `WHEN`‑условия             | сложные условия, `>=`, `BETWEEN`, строки логики |
| `CASE значение ... WHEN ...` | простое сравнение `значения` с набором констант |

## Урок 12. Условная функция IF

### 💡 Что такое IF

- `IF(условие, если_истина, если_ложь)` — простая функция ветвления в MySQL.  
- Удобно для **двузначной логики** (2 варианта).

---

### Синтаксис IF

```sql
IF(условное_выражение, значение_1, значение_2)
```

- Если условие истинно → `значение_1`.  
- Иначе → `значение_2`.

Пример:

```sql
SELECT IF(10 > 20, 'TRUE', 'FALSE');
```

Результат: `FALSE`. [web:209]

---

### Вложенные IF

```sql
SELECT
    id,
    price,
    IF(price >= 200, 'Бизнес-класс',
        IF(price >= 150, 'Комфорт-класс', 'Эконом-класс')
    ) AS category
FROM Rooms;
```

Логика:
- `>= 200` → `'Бизнес-класс'`  
- `>= 150` → `'Комфорт-класс'`  
- иначе → `'Эконом-класс'`

---

### IFNULL — замена NULL

```sql
IFNULL(значение, альтернативное_значение)
```

- Если `значение` не `NULL` → возвращается оно.  
- Если `значение` равно `NULL` → возвращается `альтернативное_значение`.

Примеры:

```sql
SELECT IFNULL('SQL Academy', 'Альтернатива SQL Academy') AS result;
-- результат: SQL Academy

SELECT IFNULL(NULL, 'Альтернатива SQL Academy') AS result;
-- результат: Альтернатива SQL Academy
```

---

### NULLIF — обратная проверка

```sql
NULLIF(значение_1, значение_2)
```

- Если `значение_1 = значение_2` → `NULL`.  
- Иначе → `значение_1`.

Пример:

```sql
SELECT NULLIF('SQL Academy', 'SQL Academy') AS result;
-- результат: NULL

SELECT NULLIF('SQL Academy', 'Другой текст') AS result;
-- результат: SQL Academy
```

### Таблица: когда что использовать

| Функция | Для чего |
|---------|----------|
| `IF`       | выбрать один из двух вариантов по условию |
| `IFNULL`   | заменить `NULL` на безопасное значение |
| `NULLIF`   | превратить совпадающие значения в `NULL` |
